## 세션 시작 시 필수 확인

매 세션 첫 작업 전에 `.claude/memory.md`를 읽고, 현재 상태(브랜치, 완료 항목, 다음 단계)를
텍스트로 한 줄 이상 출력한 뒤 작업을 시작할 것.
memory.md 내용과 모순되는 판단을 내리면 안 됨.

## /done 실행 순서 (반드시 이 순서대로)

```
1. flutter analyze         → 결과 캡처
2. flutter test            → 결과 캡처
3. Secret scan             → grep -rn "sk-\|apiKey.*=.*['\"]" --include="*.dart" lib/
4. flutter-reviewer 에이전트 실행 → 비판적 코드 리뷰 (보고만, 수정 금지)
5. 발견된 이슈 수정 (있는 경우)
6. 사용자에게 1~5 전체 결과 제시 + 승인 요청  ← 반드시 멈출 것
7. 명시적 승인 확인 후 커밋
```

**금지**: 1~6을 건너뛰고 바로 커밋하는 것.
**금지**: 자동화 체크(analyze/test)만 통과하면 커밋해도 된다고 판단하는 것.
**금지**: flutter-reviewer 없이 QA 완료로 선언하는 것.

## Approval Gate — 커밋/푸시

커밋은 "공유 상태에 영향을 주는 액션"이므로 Approval Gate 필수 적용.

커밋 전 반드시:
```
"다음 파일들을 커밋합니다:
  - [파일 목록]
커밋 메시지: [메시지]
승인하시겠습니까?"
```
형태로 제시하고, 사용자의 명시적 "예" / "진행해" / "OK" 등을 확인한 후 실행.

**금지**: 체크 결과가 통과했다고 자동으로 커밋하는 것.
**금지**: "커밋하시겠습니까?"와 커밋 실행을 같은 메시지에 묶는 것.

## Codex 역할 경계

플랜에서 "Codex 담당"으로 분류된 작업은 반드시 `/codex` 스킬로 위임할 것.
포함: 패키지 설치, 설정 파일 보일러플레이트, 위젯 구현, 테스트 생성, 구조적 파일 편집.

Claude Code가 Codex 범위 작업을 직접 처리하려면 먼저 사용자에게 이유를 설명하고 허락을 받을 것.

**금지**: "빠르니까 내가 직접 한다"는 판단으로 역할 경계를 무단 침범하는 것.

## 컨텍스트 파일 읽기 (RULE 14 강화)

작업 시작 전 관련 `.claude/context/` 파일을 읽는 것에 더해,
memory.md와 해당 task 파일(`.claude/tasks/phase1/{NN}-*.md`)을 반드시 읽을 것.

task 파일 내용과 현재 상태를 비교해서 "이미 완료된 것"을 "해야 할 것"으로 착각하지 말 것.

## 자기 점검 트리거

다음 상황에서는 작업을 멈추고 규칙 위반 여부를 점검할 것:
- 커밋 명령을 치려는 순간
- "빠르게 끝내려면" 이라는 생각이 드는 순간
- 사용자 승인 없이 다음 단계로 넘어가려는 순간
- 플랜에 적힌 담당자가 Codex인데 내가 직접 구현하고 있는 순간
